# AGENTS.md

本仓库协作与代码开发规范。任何开发者或自动化代理提交代码前必须读完并遵守。

## 角色与工作方式

- 以资深全栈工程师标准交付：代码可读、结构清晰、每次改动可验证。
- 默认直接执行，不反复请示；仅在以下情况先询问：操作不可逆、影响账户或他人数据、超出当前任务范围。
- 一次只完成指定任务，不擅自扩展范围、不改动任务外文件。完成任务所必需的辅助动作（安装依赖、本地化资源、建立部署目录等）不算越界。

## 开工前先检索

- 开工前先检索开源方案、免费资源、现有库或提示词，避免闭门造车浪费时间与 token。
- 仅对复杂或陌生任务检索，控制在 1–2 轮；简单任务直接开工。
- 长任务先做计划、拆分步骤，避免上下文淹没。

## 代码规范

- 命名语义化，格式统一（缩进、引号、空格一致）。
- 原生 HTML / CSS / JavaScript 为主，不引入框架与构建链，除非有明确必要。
- 第三方依赖 vendored 到 `assets/vendor/` 并记录名称、版本、来源与许可证；运行时不依赖外网 CDN。
- 项目默认公开；公开仓库中**禁止**出现任何密钥、token、密码或私有配置。凭据只通过本地环境变量注入，不写入任何被跟踪文件。
- 去除一切 AI 水印及代理独有水印：页面不留“由 AI 生成”类标识，代码与注释不留默认 AI 署名或生成痕迹。
- 不臆造功能、不跳过验证、不假装完成。

## 版本规则

- 版本格式为 `vX.Y`，单段次版本号，从 0 计数；次版本到 10 即进主版本：
  `v1.0 → v1.1 → … → v1.9 → v2.0`。
- 禁止 `v1.0.0`、`v1.11.0` 这类多段版本号。
- 每次发布在 `CHANGELOG.md` 记录版本、日期与变更。

## Git 规范

- 小步提交，一个提交只做一件可描述的事。
- 提交信息使用祈使句、语义清晰，建议带类型前缀：
  `feat:` 新功能 / `fix:` 修复 / `style:` 样式 / `refactor:` 重构 / `docs:` 文档 / `chore:` 杂务 / `build:` 构建与工具。
- 版本管理与日志记录非常重要，每次任务结束前必须检查：已提交、已推送、`CHANGELOG.md` 与 `TODO.md` 已更新。
- 仓库经 GitHub 管理，Cloudflare Pages 部署。

## 完成与自验证

- 每次完成后自验证并报告：优先用真实入口 / 页面截图核对用户实际看到的内容。
- 验证覆盖：功能可用、布局在桌面与移动端无溢出、控制台无错误、`prefers-reduced-motion` 兜底有效。
- 交付说明如实列出：验证方式、覆盖范围、未完成项与已知限制。

## 文档约定

- `README.md` 只做项目介绍（简介、技术栈、快速开始），不放核心实现信息。
- 重要、深入的内容下沉到 `docs/`，一个文件一个主题。
