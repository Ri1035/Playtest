# 组件开发规范

## 通用原则

### 单一职责

一个模块只做一件事。若模块名需要用"和"连接两个概念，说明该拆了。

### 无隐式全局状态

模块级变量只允许存放**只读常量**或**纯函数缓存**。任何可变状态必须有明确的所有者，通过参数传入。

反例（本项目已修复的真实问题）：

```js
// ❌ 用模块级可变变量把"是否是陆地"的查询函数传给绘图函数
let landLookup = null;
export function setLandLookup(tiles) { landLookup = tiles; }
```

这种写法让函数的正确性依赖外部调用顺序，且测试时极易漏设。应改为显式传参：

```js
// ✅
function drawLandTile(ctx, gx, gy, tile, tilePx, isLand) { ... }
```

### 无魔法数字

尺寸、时长、阈值一律命名或定义常量。图形绘制的关键参数必须有注释说明"为什么是这个值"——尤其是网点半径这类经验值，修改后必须重新截图确认。

## Canvas 绘制规范

### 分层

每个绘制函数遵循同一顺序：

```
1. save()
2. 设置变换（translate / scale）
3. 绘制色块（fillStyle + 填充路径）
4. 叠加网点（fillDots）
5. 描边（inkStroke）
6. 绘制装饰细节
7. restore()
```

描边在网点之后，保证黑色线条不被网点覆盖。

### 变换必须配对

每次 `save()` 都要有对应的 `restore()`。绘制函数内部自行管理变换，不改变调用方的上下文状态。

```js
// ✅ 动画通过 ctx.scale 实现，不污染外部
ctx.save();
ctx.translate(cx, cy);
ctx.scale(bounce, bounce);
// ... 绘制 ...
ctx.restore();
```

### 图案填充

网点填充统一走 `fillDots(ctx, x, y, w, h, pattern, alpha)`，不直接调用 `fillStyle = pattern`。

**原因**：该函数统一处理了 `globalAlpha` 的保存恢复。直接赋值会污染后续绘制的透明度。

## 颜色规范

### 唯一来源

所有 Canvas 绘制用色从 `render/palette.js` 导入。禁止在绘制函数中写字面色值。

例外：描边色与投影黑允许直接用 `INK`，因为它们是设计系统级别的常量而非具体色板成员。

### 透明度

`rgba()` 仅用于描边与投影，且 alpha 不低于 0.16。半透明彩色叠加模拟色调是被禁止的——这是波普规范的红线，网点是唯一的明暗手段。

## 动画规范

### 时间驱动

生命周期基于 `dt`（毫秒增量），不基于帧数。

```js
// ✅
bounce = 1 + Math.sin(time / 320) * 0.035;

// ❌ 会导致不同刷新率下速度不一致
bounce = 1 + Math.sin(frameCount / 20) * 0.035;
```

### 动画风格

波普风格的动效是**机械的、离散的**，不是平滑的：

- 使用正弦函数产生规律抖动，不用缓动函数
- CSS 过渡只用 `steps()`，保留逐格跳变感
- 缩放振幅控制在 0.05 以内，大幅形变会破坏印刷质感

## 状态管理规范

### 写入口唯一

所有对 `state` 的修改必须经过 `core/state.js` 导出的函数。

**理由**：存档与 HUD 刷新挂钩在这些函数上。若某处直接改 `state.resources`，会导致该变化不持久化且 HUD 不同步。

### 新增状态字段的检查清单

- [ ] 加入 `createGame()` 的初始化
- [ ] 加入 `saveGame()` 的 payload
- [ ] 加入 `loadGame()` 的读取与校验
- [ ] 若影响玩法，加入对应单元测试

## 错误处理

### 容错而非崩溃

用户数据（存档）不可信，读取必须校验。校验失败降级为新档，不抛异常。

```js
// ✅
try {
  const data = JSON.parse(raw);
  if (typeof data.seed !== 'number' || !Array.isArray(data.tiles)) return null;
  // ...
} catch (err) {
  return null;
}
```

### 不吞掉真实错误

`catch` 只包裹预期会失败的、来自外部不可信输入的操作（存档读写、音频上下文创建）。**不要**用空的 `catch` 掩盖代码 bug——那会让问题静默存在。

注释要说明为何可以忽略：

```js
} catch (err) {
  // 隐私模式下 localStorage 抛异常，属预期内情况，不打断游戏
}
```

## 音效规范

音效由 `ui/audio.js` 用 WebAudio 参数合成，不引入音频文件。

新增音效时：

1. 在 `presets` 中加条目（频率、结束频率、时长、波形）
2. 起始与结束频率用 `exponentialRampToValueAtTime`，避免音高突变产生爆音
3. 增益必须指数衰减到接近零（`0.0001`），不能直接归零

## 文档规范

### 注释写"为什么"

```js
// ✅
// 错位排布：对角线方向的网点比正交排列更接近手工丝网印的质感
const offset = cell / 2;

// ❌
// 对角线偏移
const offset = cell / 2;
```

### 导出函数写 JSDoc

对参数有约束或返回值有语义的函数，用 JSDoc 说明：

```js
/**
 * 在给定区域内绘制网点覆盖层。
 * 波普配色的关键：网点层用 alpha 控制在 25%~55% 之间，
 * 低于 25% 看不见，高于 55% 就糊成实色，失去印刷质感。
 */
```

注意：注释中的数值必须与代码实际值一致。规范与实现脱节比没有规范更危险。
