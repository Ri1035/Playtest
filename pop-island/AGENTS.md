# 项目协作与代码开发规范

## 一、开发准则

### 开工前先检索

对复杂或陌生任务，先检索开源方案、免费资源、既有实现，最多 1–2 轮。简单任务直接开工，不做无谓检索。避免闭门造车浪费时间和 token。

### 范围控制

一次只完成指定任务。不擅自扩展范围，不改动任务外文件。

完成指定任务所必需的辅助动作（安装依赖、本地化资源、创建部署目录等）不算越界。

### 默认直接执行

不反复请示。仅当操作满足以下任一条件时先询问：

- 不可逆操作（删除数据、覆盖存档、发布公开内容）
- 影响账户或他人数据
- 超出任务范围

### 禁止事项

- ❌ 臆造功能：声明完成的功能必须真实可用
- ❌ 跳过验证：未验证不报告完成
- ❌ 假装完成：失败要明确说明失败原因

## 二、代码规范

### 命名

语义化、可读、含义明确。

- 文件与目录：小写中划线（`patterns.js`），例外为入口 `index.html`
- 变量与函数：`camelCase`
- 常量：`UPPER_SNAKE_CASE`
- 类：`PascalCase`
- 禁止无意义缩写（`fbm` 可接受，因为它是领域通用术语；`tmp`、`data2` 不可接受）

### 格式

- 统一 2 空格缩进
- 单引号优先，模板字符串用于插值
- 尾随逗号
- 单文件保持内聚，一个模块只负责一件事

### 注释

**注释解释"为什么"，不解释"做了什么"。**

```js
// ✅ 解释设计意图
const price = Math.floor(bounce); // 商业游戏惯例取整到分，避免浮点误差累积

// ❌ 复述代码
const price = Math.floor(bounce); // 取整价格
```

### 水印与署名

去除一切生成工具水印及智能体默认署名：

- ❌ 页面不出现"由 AI 生成"类标识
- ❌ 代码注释不包含默认署名或生成痕迹
- ❌ 不添加无实际意义的装饰性注释

## 三、验证要求

每次任务结束前必须自验证并报告结果。

### 验证层级

| 改动类型 | 最低验证要求 |
| --- | --- |
| 纯数值/逻辑 | 单元测试通过 |
| Canvas 绘制 | **截图目视确认**，不能只看代码 |
| DOM/交互 | 浏览器自动化断言 |
| 部署后 | 线上地址真实可访问 |

**截图验证是强制的。** 波普风格的成败完全取决于网点参数是否正确，而这无法通过阅读代码判断。

### 报告内容

- 执行了哪些验证
- 验证结果（通过 / 失败数量）
- 发现并修复的问题
- 未验证或存在风险的部分

## 四、Git 规范

版本管理与日志记录非常重要，每次任务结束前必须检查是否写入。

### 提交粒度

**小步提交。** 一个提交只做一件事。禁止把"新功能 + 修 bug + 改文档"混在一次提交里。

### 提交信息

格式：

```
<type>(<scope>): <简短描述>

<正文：为什么这样改，而非改了什么>
```

type 取值：`feat` 新功能 / `fix` 修复 / `style` 样式 / `docs` 文档 / `refactor` 重构 / `test` 测试 / `chore` 杂项 / `perf` 性能

示例：

```
feat(render): 放大Ben-Day 网点半径至 2.3px

原参数 1.7px 在 0.94 缩放下被插值抹平，网点几乎不可见，
波普风格的视觉签名因此丢失。同步提高覆盖透明度至 0.62，
并为草地增加双色交错以区分大片同色区域。
```

### 提交前检查

- [ ] `git status` 确认没有误提交临时文件
- [ ] `.gitignore` 覆盖 `node_modules/`、`.devtools/` 产物、`.env`
- [ ] 无 token、密钥、密码进入提交
- [ ] CHANGELOG.md 已更新
- [ ] 验证已执行且通过

## 五、文件组织

```
根目录
├── AGENTS.md          协作与开发规范（本文件）
├── README.md          项目简介、技术栈、快速开始
├── DESIGN.md          视觉风格、布局、交互规范
├── CHANGELOG.md       版本更新记录
├── TODO.md            开发计划与进度
└── docs/              下沉文档
    ├── PROJECT-SPEC.md
    ├── ARCHITECTURE.md
    ├── COMPONENT-GUIDELINES.md
    ├── PAGE-STRUCTURE.md
    ├── DEVELOPMENT.md
    ├── REGISTRY.md
    └── DEPLOYMENT.md
```

README 只做项目介绍，不放核心信息。重要内容下沉到 `docs/`。

## 六、安全红线

- 用户提供的 Token **绝不写入任何文件**、提交记录、git remote 或 `.git/config`
- 推送时 Token 内联在临时 URL 中，不落盘；remote 只保留干净的 `https://github.com/<user>/<repo>.git`
- 交付后主动提醒用户轮换已在对话中暴露的凭据
- 默认创建**私有**仓库（公开不可逆，私有随时可改）

## 七、部署

GitHub 管理代码，Cloudflare Pages 托管静态文件。

本项目为纯静态站点，无构建步骤，直接上传源目录。详见 `docs/DEPLOYMENT.md`。
