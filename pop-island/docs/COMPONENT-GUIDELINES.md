# COMPONENT-GUIDELINES.md — 组件开发、样式、依赖与无障碍规范

本文件规范游戏内各组件的开发方式，新增玩法元素 / 装饰 / UI 时按此执行。

## 组件分类

| 类别 | 位置 | 说明 |
| --- | --- | --- |
| 精灵绘制函数 | `sprites.js` | 纯函数：`(ctx, x, y, s, ...) => void`，只画不持有状态 |
| 实体类 | `entities.js` | 持有位置与生命周期状态，不含绘制逻辑 |
| 注册表 | `sprites.js`（ITEMS/POWERUPS）| 元数据 + 绘制函数绑定 |
| 游戏系统 | `engine.js` | 组件之间的编排（碰撞、生成、计分） |
| DOM 组件 | `index.html` + `styles.css` + `main.js` | HUD / 菜单 / 暂停 / 遮罩 |

## 精灵绘制规范

1. 所有绘制函数**不得依赖 Math.random**（闪烁问题）：动态效果用调用方传入的时间/相位参数。
2. 描边统一 `INK = '#111111'`，线宽随尺寸 `s` 缩放。
3. 新元素加入 `ITEMS` 注册表时必须提供：`r`（碰撞半径）、`worth`（基础分）、`color`（飘字/粒子色）、`draw`（绘制函数）。
4. 静态装饰（棕榈/花/岩石/罐）绘制在岛屿离屏层，由 `world.js` 的 `makeDecorations()` 生成位置。

## 样式规范

- 颜色只允许取自 `:root` CSS 变量或 `PALETTES` 调色板，禁止散落硬编码 hex。
- 按钮必须使用 `.pop-btn` 或 `.hud-btn` 基础类（粗描边 + 硬阴影 + 按压位移反馈）。
- HUD 数字更新走引擎 `updateHUD`，CSS 只负责外观，禁止在 CSS 中复制游戏状态。
- 新增覆盖层按 z-index 分层表（见 ARCHITECTURE.md）放置。

## 依赖规范

- **零运行时依赖**：禁止引入 npm 运行时包；构建期仅允许 devDependencies（目前仅 Vite）。
- 禁止外链字体 / CDN / 图片：任何新增视觉或音频资源必须本地化或程序化生成。
- 浏览器 API 使用前检查兼容性，必要时在 `main.js` 加最小兜底（如 `roundRect`）。

## 无障碍规范

- 所有 `<button>` 有可读文本或 `aria-label`。
- 颜色不作为唯一信息通道：连击/受击/升级均有文字或图形反馈。
- 不依赖 hover 才能完成的交互（触屏无 hover）。
- 焦点样式保留浏览器默认（本游戏无键盘 Tab 表单流程，按钮仍应可聚焦）。
- 后续新增常驻循环动画时，提供 `prefers-reduced-motion` 降级。

## 性能约束

- 动态实体每帧绘制数量有上界（元素 ≤ ~24、海鸥 ≤ 8、粒子 ≤ ~200），新增实体类型先估算。
- 离屏图层（海面/岛屿）只在调色板或等级变化时重建，禁止每帧重建。
- `update()` 内避免字符串拼接等 GC 热点；飘字/粒子数组使用反向索引遍历 + splice。
